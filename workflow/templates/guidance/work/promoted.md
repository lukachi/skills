# What the project now says about itself

This is the second and last thing the maintainer is asked.

A page in curated knowledge is the project speaking about itself. It is what
every later session reads first and what the next framing is aligned against, so
it is worth their attention in a way a closure receipt is not — an auditor reads
a receipt once, if ever.

Keep the two roads separate. A product page explains current behaviour to
stakeholders and carries no code, identifiers, endpoints, or paths. An
engineering page explains realization to engineers, and links established
product meaning rather than inferring intent from the code.

Do not type a path. The tool creates each draft where it belongs and prints it.
