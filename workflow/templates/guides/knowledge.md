
## Knowledge repository practice

Work in bounded topics, not by attempting to rewrite the entire legacy corpus
at once.

1. Select one domain, decision chain, capability, or repository boundary.
2. Query Graphify across related raw records, curated concepts, and available
   code evidence.
3. Separate original intent, later decisions, implementation reality,
   superseded behavior, and unresolved claims.
4. Present only unresolved authority questions and material proposed truth to
   the maintainer.
5. Write the smallest useful set of OKF concepts.
6. Update affected indexes and newest-first logs.
7. Keep superseded concepts with `status: deprecated` and links to successors.

The maintainer is not expected to review mechanical indexing or every
source-backed implementation fact. Focus human attention on intent, semantics,
decisions, contradictions, and claims whose authority cannot be established
from evidence.

Start with `knowledge/index.md`. Treat `knowledge/uncertainties/` as a valid
destination, not a failure state.
