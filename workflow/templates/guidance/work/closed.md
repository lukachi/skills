# Closing

Nobody is asked.

Closure asks whether the work matches the framing that was approved, and every
part of that answer is in the record already: verified criteria, passed receipts,
pinned revisions, terminal units. One night spent waiting on that question cost
seven hours and fifty-four minutes and two of four approved records.

One refusal here is a real question rather than an errand: **delivery no longer
matches the approved framing**, because the criteria were reworded since they
agreed to them, or work left the route. That one goes back to them.

## Write what the project now knows, first

Decide whether verified durable truth changed, and draft the pages while the
understanding is fresh — under the record's own `promotion/` directory, at the
exact path each will occupy in curated knowledge. Nothing enters the corpus here.

A page promoted from a record in a project with no reconstructed baseline has the
same shape as one established by whole-project reading and a far narrower
footing: it came from whatever this task happened to touch. Say so in its source
— name the record, state that no reconstruction has covered this subject — so a
later baseline re-derives it instead of trusting it. Draft it anyway.

Account for every answer the maintainer gave. A resolved direction map is the
checklist that accounting is held against.

## Order matters, because each step invalidates the one before

Every semantic edit first. Then the checkpoint, before the final hash receipt — a
checkpoint edit changes the file's hash, so a receipt taken ahead of it is stale
on arrival. Then re-read everything the review changed and refresh those
receipts. Then verify, then close.

Use the honest outcome. Partial and abandoned are results, and a completed that
had to be argued for is the one worth doubting. A record closing with drafted
pages waits in the promotion queue rather than the archive, whatever its outcome
— a partial delivery is exactly when there is most to say.
